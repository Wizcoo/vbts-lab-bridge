# 双端流程

## 分支与审核

主分支保存已审查工具与合同。实验室使用 `codex/lab-<session-id>`，分析端使用 `codex/analysis-<task>`。默认不 force push、不自动合并、不自动部署。

1. 发起任务：说明要验证哪一层、允许的动作、输入身份、命令、预期产物和停止条件。
2. 执行端记录实际 checkout 提交、工作区改动、设备与程序身份。任务开始后不悄悄升级依赖或模型。
3. 实验室采集前确认设备可用；未连接记录 BLOCKED，保留已完成的离线工作。
4. 每个 session 独立目录；封存实际数据包，提交 session_manifest、审核摘要及附件身份。附件不可只写本地绝对路径供异机下载；本地路径仅作来源，交接必须有接收端可访问的批准位置。
5. 分析端下载后复核 SHA256、字段、单位和时间轴，先不改模型。按原始帧 -> 位移场 -> 最终张量 -> ONNX 原始输出 -> 显示/力计标签定位首次差异。
6. PR 留审核结论、证据路径和下一轮任务。通过的代码可合并；模型替换另需明确现场授权。

## 首轮的有限范围

先验收交接是否完整、可读、可复算；不同时训练或调多套模型。没有 SDK 张量、原始力流、坐标或同步证据时，明确限制，不能以指标高掩盖缺口。

## 大文件

选项 A：小型诊断数据逐文件审查后随 PR 提交，优点是简单，缺点是历史体积永久增长。
选项 B：大文件留私有 Release 附件或另行批准的私有存储，Git 仅保存清单/哈希/访问位置，优点是仓库轻量，缺点是接收端需有附件访问权。

当前选择：代码与元数据进 Git；完整图像/张量/模型包走 B。首轮实际传输位置待账号通道确定后记录，不能伪造下载地址。不自动启用付费存储或扩大访问权限。
